# CordisX 用户更新协调

在用户要求安装或更新 CordisX 或其插件时读取本规则。
本规则约束 agent 的交付责任；具体命令和生命周期能力以当前版本的
Host 文档、CLI 帮助及实际读回为准。

- 用户要求更新后，由当前 agent 负责实际安装、激活和读回验证。
  不要让用户关闭承载当前 agent 的 App，再假定自己仍能在后台完成；
  用户重启也不等于插件更新已执行。
- 先通过正式、普通 CLI 的 status 和 plugin list 核对真实运行版本、
  实例、profile、插件版本及状态。依据当前版本的公开生命周期能力选择操作，
  不沿用旧版本的失败结论。
- 优先使用支持的直接热更新。目标插件占用独占端口等资源时，检查是否支持
  仅对目标插件执行 disable → update → 必要时 enable，保留 Host、App
  和其它插件服务；update 已恢复 enabled/active 时不要重复 enable。
- “插件服务需要重启”不等于“整个 App 必须退出”。在更新授权范围内完成
  目标插件的常规生命周期操作，不反复请求相同授权；不得自行关闭、重启、
  重载整个 App 或无关服务。真正新增的插件权限仍须用户决定。
- 只有当前版本确实支持并能持久读回时，才可采用下次启动生效的更新方式。
  不得伪造 inactive 状态、绕过真实实例选择或编造 next-start 队列。
- 更新后核对精确版本、包 digest/source、enabled/active 与 pendingActivation，
  并确认 Host 实例和无关插件服务没有意外变化。分别报告已发布、已安装、
  已生效；只监控或只生成计划时，不得说“正在后台更新”或“已完成”。
- 若确有无法继续的限制，说明实际版本、受限操作和证据，并继续承担协调责任；
  不要仅把操作转交用户或反复催其退出。
