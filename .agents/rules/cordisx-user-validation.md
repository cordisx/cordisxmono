# CordisX 用户环境验收

在为用户启动 CordisX 测试实例、原生预览或验收模型服务时读取本规则。
具体启动方式和数据模式以 Host 的
[启动参考](https://github.com/cordisx/cordisx/blob/main/.agents/docs/distribution-and-cli.md)
为准。

- “隔离测试”默认隔离进程、Chromium profile、测试配置和临时输出，
  同时复用用户已有登录态和已经运行的目标插件服务。
  不得把用户允许独立测试实例理解为要求隔离账号。
- 默认采用 Host 支持的 `shared` 模式。只有用户明确要求独立账号，
  或待验证问题本身必须使用全新账号根时，才采用 `host-isolated`。
  已有会话约定优先；不要每次重新询问已经确定的登录复用偏好。
- 启动前读回并记录数据模式、实际 `HOME` / `CODEX_HOME`、
  独立 Chromium 目录、配置来源、目标插件服务身份和测试实例归属。
  只记录身份与路径，不读取或输出凭据内容。要求复用登录时，
  账号根必须与已确认的用户根一致；不一致先修正测试计划。
- 使用正式共享登录机制，不复制凭据、登录文件、数据库，
  不复制或并发打开用户的系统 Chromium profile。
  不修改用户全局配置来临时加入测试服务商。
- 保持现有 App、聊天和无关服务运行。测试仅操作明确拥有的实例；
  清理前核对 PID、启动身份和 profile，清理后核对现有实例未变。
- 区分测试环境问题与产品缺陷。出现新登录或欢迎流程时先核对数据模式，
  不立刻要求用户重新登录或反复解锁；说明实际证据和尚未完成的验收。

项目内的规则修改不应写入用户的全局 `AGENTS.md`。
